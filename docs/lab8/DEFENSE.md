# Защита ЛР №8

Вариант: с нуля, собственный дизайн. Бонус: SEO + ISR; дополнительно CSR и сравнение.
Команды запуска: [storefront/README.md](../../storefront/README.md).

## Сценарий

1. Открыть `/menu`: это публичная серверная витрина.
2. Ctrl+U: найти название блюда и цену в реальных HTML-тегах, а не только в React payload.
3. Открыть блюдо `/menu/1`: название, цена, доступность, переход к оформлению в старом SPA.
4. Ctrl+U: показать title, description, og:title, canonical.
5. Открыть `/menu-csr`: в исходном HTML блюд нет, запрос появляется в Fetch/XHR после JS.
6. Показать экран ошибки и retry на некешированной карточке при выключенном API.
7. Показать loading при переходе с меню к новой карточке при медленной сети/API.
8. В production показать ISR: цена остаётся старой сразу после PATCH, обновляется после TTL
   и фоновой регенерации. Изменять данные только на отдельном тестовом стенде.
9. Показать таблицу трёх замеров и выводы в README, результаты проверки и скриншоты.

## Ответы

**Server и Client Components.** Серверная страница получает данные до выдачи HTML.
Клиентская получает useState/useEffect и обработчики; пример — `/menu-csr` и error.tsx.
Само наличие `'use client'` не отменяет предварительную разметку оболочки на сервере:
в нашем CSR-задании именно данные блюд загружаются только useEffect.

**Почему SSR.** В публичном меню важны готовые названия/цены в документе и SEO.
Кабинет требует интерактивности и может оставаться SPA.

**Как проверить.** Ctrl+U или curl с поиском HTML-карточек. DOM после JS не доказывает SSR.

**loading/error.** Skeleton на ожидании и понятная ошибка с повтором. Ошибка API и 404 —
разные случаи. Закешированный HTML способен скрывать недоступность API.

**params Promise.** App Router предоставляет params асинхронно: используем await params
перед чтением id; нельзя читать id как синхронное поле Promise.

**Кеши.** Redis хранит данные меню в backend, Next Data Cache — ответы серверного fetch,
Full Route Cache — готовый HTML/RSC. Отключение browser cache не выключает ISR.

**Open Graph.** Метаданные для превью ссылок; title — вкладка/поиск, description — описание.
SVG-превью включено как кодовый ресурс; поддержка SVG зависит от внешнего клиента.

**BFF.** Слой под потребности фронтенда. В работе выбран REST и бонус SEO/ISR, поэтому
GraphQL не обязателен. `/api/menu/items` в Next — простой same-origin прокси для CSR
в отдельном локальном запуске, не GraphQL BFF.

**Замеры.** Не путать FCP шапки с появлением блюд. Метод, окружение, кеши и все три прогона
записаны в результатах; прогретый ISR ожидаемо уменьшает работу на сервере для повторных запросов.
