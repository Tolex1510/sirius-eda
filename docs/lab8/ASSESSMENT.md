## Главное

Текущий веб-интерфейс покрывает пользовательские сценарии учебной практики,
но пока не выполняет основной критерий ЛР №8: серверный HTML с блюдами.
Фронтенд — React + TypeScript + Vite + React Router; данные загружаются в браузере.
В `frontend/index.html` есть пустой `div#root`, содержимое создаёт `createRoot`.
Наличие меню на экране и кеша Redis само по себе не является SSR/ISR.

Методичка разрешает вариант «с нуля»: повторять внешний вид и структуру шаблона
не требуется. Проверяемые результаты SSR, маршруты, обработка ошибок и бонусные
задания при этом остаются обязательными для соответствующего балла.

## Матрица требований

| Требование | Сейчас | Что осталось |
| --- | --- | --- |
| TypeScript и интерфейс меню | Есть | Переиспользовать дизайн и модели |
| Запросы к REST API | Есть, браузерный `fetch` | Серверная загрузка для публичных страниц |
| Next.js App Router | Нет, используется Vite | Добавить публичную витрину на Next.js |
| `/menu`: серверный HTML с названиями блюд | Нет; меню находится на `/` и рендерится в браузере | Server Component со списком |
| `/menu/[id]`: серверный HTML с названием и ценой | Нет отдельной страницы блюда | Динамический маршрут, проверка параметра и `notFound()` |
| `GET /menu/items` | Есть | Использовать существующий эндпоинт |
| `GET /menu/items/{id}` | Нет | Добавить чтение через сервис меню; репозиторий уже умеет `get_by_id` |
| Загрузка и ошибка с повтором | Есть скелетоны и `ErrorBox` в SPA | Добавить `loading.tsx` и клиентский `error.tsx` для SSR-маршрутов |
| Отсутствующее блюдо → 404 | Нет отдельного маршрута | Различать 404 от API и недоступность API |
| SEO | Есть общий статический title/description | Метаданные блюда: title, description, Open Graph |
| ISR, 60 секунд | Нет | `revalidate = 60` и кеш серверного fetch; проверка в production |
| GraphQL BFF | Нет | Не требуется при выборе бонуса SEO + ISR |
| `/menu-csr` | Нет отдельного сравнительного маршрута | Реализовать клиентскую версию на том же API |
| Три замера SSR и три CSR | Нет | Chrome DevTools; условия, результаты и выводы в README |
| Памятка для защиты ЛР №8 | Нет | Добавить после реализации и фактических проверок |

В методичке указан Tailwind CSS; текущий дизайн написан на обычном CSS. Этот
дизайн можно сохранить. Отказ от шаблона не отменяет Next.js/SSR, явно указанные
в теме и критериях работы.

## Что сохраняем

- Дизайн, карточки, иллюстрации, адаптивную сетку, поиск и категории.
- Регистрацию и вход, оформление и оплату, заказы, доставку, кабинеты и ассистента.
- FastAPI, архитектуру модулей меню и существующий REST API.
- Проверки браузерных сценариев оплаты; их нельзя считать проверками SSR.

## Предлагаемый порядок до полного набора требований

1. Добавить публичное чтение отдельного блюда: сервис, маршрут, 404.
2. Добавить Next.js-витрину `/menu` и `/menu/[id]` в существующем стиле;
   интерактивные кабинеты можно оставить SPA, как допускает теоретическая часть лабы.
3. Добавить состояния загрузки, ошибки с повтором и отсутствующего блюда.
4. Выбрать бонус SEO + ISR, не вводя GraphQL ради альтернативного задания.
5. Добавить `/menu-csr`, выполнить по три замера каждого варианта.
6. Записать результаты, команды запуска и ответы для защиты в README/документацию.

Для защиты проверить сырой HTML или Ctrl+U, а не только DOM после выполнения JS.
При проверке ошибки учитывать ISR: уже закешированная страница может продолжать
открываться при остановленном API. Проверять некешированный маршрут, отдельно
показывать 404 при работающем API и ошибку соединения при выключенном API.
Проверку ISR выполнять через production build/start; обновление может происходить
в фоне после истечения интервала, поэтому проверить и следующий ответ.

## Где смотреть текущий код

- `frontend/package.json`: стек Vite/React, команды сборки.
- `frontend/index.html`: исходная HTML-оболочка без данных меню.
- `frontend/src/main.tsx`: Menu, загрузка через useEffect, маршруты SPA, скелетоны/ErrorBox.
- `frontend/src/api.ts`: браузерный REST-клиент и типы.
- `frontend/src/style.css`: оформление, которое можно сохранить.
- `frontend/nginx.conf`: выдача index.html для маршрутов и проксирование `/api`.
- `app/modules/menu/router.py`: существующие маршруты списка, категорий и редактирования.
- `app/modules/menu/service.py`: бизнес-логика меню.
- `app/modules/menu/repository.py`: существующий поиск блюда `get_by_id`.
- `frontend/e2e/checkout.spec.ts`: имеющиеся проверки SPA и платежей.
