# Локальный ассистент и семантический поиск

Сайт использует существующую Ollama в WSL компьютера с Хоши. Для ответов — `qwen2.5:3b-instruct-q5_K_M`, для эмбеддингов — `bge-m3:latest` (1024 измерения). Модели не дообучаются: ответы строятся из актуальных данных и найденных источников (RAG).

## Как устроено

- `app/modules/assistant/ollama.py`: HTTP-клиент Ollama; системный HTTP-прокси отключён, соединение ограничено 5 секундами. Генерация — контекст 8192, до 350 токенов. BGE работает на CPU другого ПК, Qwen может использовать его GPU.
- `app/modules/assistant/repository.py`: индекс блюд и публичной справки в pgvector, поиск по cosine distance; история и заказы ограничены текущим пользователем. Цена, состав и доступность источника перечитываются из БД.
- `app/modules/assistant/quality.py`: обнаружение циклических повторов; при некорректной генерации ответ составляется из найденных источников. Зацикленные старые сообщения исключаются из контекста.
- `app/modules/assistant/service.py`: системные правила, сбор контекста, вызов модели и сохранение диалога. Общий обзор меню и статус последнего или явно указанного заказа выдаются напрямую из БД (`mode=facts`) с проверкой владельца, без генерации номера, суммы и статусов. Ассистент не выполняет оплату и отмену.
- `app/modules/menu/semantic.py`: поиск меню по эмбеддингу с небольшим усилением совпадений слов; кеш векторов запросов в Redis на 5 минут. Архивные и недоступные блюда исключаются.
- `app/modules/menu/filters.py`: явные ограничения типа блюда, веганской/вегетарианской рецептуры и бюджета «до N» проверяются по актуальным данным отдельно от similarity score.
- `GET /menu/search?q=…`: публичный поиск, ограничение 20 запросов в минуту. Ответ содержит `items` и `mode=semantic|keyword`; при недоступной модели/пустом индексе используется поиск по словам.
- `storefront/src/components/MenuSearch.tsx`: тот же поиск на публичной SSR-витрине; исходный HTML по-прежнему содержит блюда, ISR страницы сохраняется на 60 секунд.
- `frontend/src/pages/Menu.tsx`: кнопка «По смыслу» и Enter в строке поиска. Обычный поиск по словам остаётся доступным при вводе. Изменение текста отменяет предыдущий запрос.
- `frontend/src/pages/Assistant.tsx`: чат, история текущего разговора и ссылки на источники.

Индекс включает 48 блюд и 5 разделов `docs/knowledge/service.md`. Миграция `0014` очищает только производные knowledge chunks и меняет размерность с 768 на 1024. История чатов, пользователи и заказы сохраняются. Индексация выполняется пакетами по 8 документов, повторно изменяются только документы с новым checksum/моделью. Периодическая задача Celery обновляет индекс каждые 5 минут.

## Подключение к ПК с Хоши

На ноутбуке нужен разблокированный админский SSH-ключ, уже разрешённый на ПК. Пароль ключа вводится только в терминале:

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/hoshi_pc
```

В локальном `.env`:

```dotenv
OLLAMA_URL=http://ollama-remote:11434
OLLAMA_HOST_HEADER=localhost:11434
OLLAMA_MODEL=qwen2.5:3b-instruct-q5_K_M
OLLAMA_EMBED_MODEL=bge-m3:latest
AI_TIMEOUT=180
OLLAMA_SSH_HOST=100.84.145.91
OLLAMA_SSH_USER=tolex
```

Запустить из того же терминала:

```bash
scripts/ollama_tunnel.sh start
scripts/ollama_tunnel.sh status
```

Скрипт сохраняет путь текущего SSH-agent в локальный `.env` и запускает Compose-профиль `remote-ai`. В `.local/ollama-ssh` копируются только публичный ключ и known_hosts. Приватный ключ не копируется в контейнер. При первом подключении к новому хосту сначала нужно подтвердить его ключ обычным SSH; туннель использует StrictHostKeyChecking=yes.

`ollama-remote` — внутренний Docker-сервис без опубликованного порта. Он пересылает HTTP через SSH на `127.0.0.1:11434` Windows, откуда localhost forwarding ведёт к Ollama в WSL. Параметр Host нужен проверке локального адреса в Ollama. При обрыве SSH повторяется подключение через 5 секунд. Настройки Хоши и её сервис Ollama не меняются.

Применение к уже работающему проекту:

```bash
docker compose -p sirius-eda build api web
docker compose -p sirius-eda run --rm init alembic upgrade head
docker compose -p sirius-eda --profile remote-ai up -d --no-build api worker web ollama-remote
docker compose -p sirius-eda exec -T api python -c 'from app.tasks.maintenance import index_assistant_knowledge; print(index_assistant_knowledge())'
```

Если нужна трассировка и запущен monitoring, перед Compose-командами добавить `OTEL_EXPORTER_OTLP_ENDPOINT=http://jaeger:4317`.

После перезагрузки ноутбука SSH-agent может получить другой путь и забывает разблокированный ключ: снова выполнить ssh-add и `scripts/ollama_tunnel.sh start`. Скопировать один путь агента навсегда недостаточно. Компьютер с WSL должен быть включён и доступен. Если он выключен, чат сообщает о недоступности модели, меню продолжает работать и поиск переходит на слова. Первый запуск моделей после простоя существенно медленнее повторных запросов.

Остановить только соединение с моделью:

```bash
scripts/ollama_tunnel.sh stop
```

## Что попробовать

В меню выбрать вкладку «По пожеланиям», ввести фразу и нажать «Подобрать». Вкладка «По названию» фильтрует названия отдельно и не вызывает модель:

- «тёплый суп без мяса»;
- «кофейный напиток с молочной пеной»;
- «веганский обед до 250 рублей».

В чате после входа:

- «Посоветуй два блюда без мяса до 250 рублей. Назови цены»;
- «Сколько стоит капучино?»;
- «Что с моим последним заказом?».

Рецептурные маркеры не гарантируют отсутствие следов аллергенов. Модель может ошибаться; ссылки на источники и карточки заказов позволяют проверить факты. Замеры и подтверждённые сценарии — в `docs/assistant/RESULTS.md`.

Документация API Ollama: https://github.com/ollama/ollama/blob/main/docs/api.md.
