# Меню «Сириус.Еда» — учебный каталог

48 блюд и напитков, 8 разделов. Цены и рецептуры придуманы для учебного проекта.

Основные данные для будущего импорта: `catalog.json`. Порция указана для блюда целиком, включая гарнир и соус. `vegetarian` допускает молочные продукты, яйца и мёд; `vegan` — без ингредиентов животного происхождения. Маркеры описывают рецептуру, а не отсутствие следов аллергенов. Калорийность не указана: её нужно рассчитывать по технологическим картам.

Каталог подключён к модели MenuItem, API, React SPA, SSR-витрине и источникам ассистента. Миграция `0013` добавляет метаданные; `python -m deploy.import_menu` обновляет каталог по стабильному slug и архивирует остальные позиции без удаления истории заказов. Повторный импорт не создаёт дубликаты, но восстанавливает цены и доступность из JSON. Импорт очищает только кеш меню и старые меню-эмбеддинги; индекс ассистента пересоздаётся после подключения Ollama. Новый пустой стенд получает каталог автоматически из `deploy.seed`.

Для обновления существующего стенда:

```bash
docker compose -p sirius-eda build api
docker compose -p sirius-eda up -d db redis rabbitmq
docker compose -p sirius-eda run --rm --no-deps init sh -c 'alembic upgrade head && python -m deploy.import_menu'
COMPOSE_PARALLEL_LIMIT=1 docker compose -p sirius-eda up -d --build
```

После импорта публичные списки не показывают архивные блюда. Старые карточки доступны по ID с признаком недоступности, чтобы заказы сохраняли названия. При переимпорте на работающем стенде SSR-кеш может обновляться до 60 секунд; перезапуск storefront сбрасывает его память.

## Фотографии блюд

Для всех 48 позиций сгенерированы отдельные иллюстративные фотографии в едином стиле: светлая посуда, мягкий дневной свет и шалфейный фон. Это изображения для учебного каталога, а не съёмка реальной кухни.

Готовые WebP находятся в `frontend/public/menu-images/` и `storefront/public/menu-images/`; manifest — `data/menu/images.json`. Размер — 960×640, суммарно около 2,66 MiB на приложение. Оригиналы хранятся локально в `.local/menu-source/` и в каталоге генератора. После установки зависимостей storefront команда `node scripts/prepare_menu_images.mjs` повторно создаёт WebP из оригиналов.

API вычисляет `image_url` по стабильному `catalog_slug`, поэтому миграция БД для фотографий не нужна. Фото используется в меню SPA, оформлении, карточках заказов и SSR-странице блюда. Для старых позиций без фотографии остаётся прежняя иллюстрация. Nginx отдаёт `/menu-images/` как статические файлы с кешем на 7 дней.

Проверка фотографий: все 48 URL отдают HTTP 200 и `image/webp`, содержимое всех файлов уникально. SSR-карточка содержит адрес изображения. В Chromium проверены карточки SPA и загрузка видимых фотографий; остальные подгружаются при прокрутке. Production-сборки обоих интерфейсов прошли, Python: 326 passed, 1 skipped. Превью текущего сайта сохранено локально в `.local/menu-photos-preview.png`.
