# Веб-интерфейс Сириус.Еды

React + TypeScript + Vite. Здесь находятся интерактивные кабинеты, оформление,
демо-оплата, заказы, трекинг и ассистент. Публичная SSR-витрина ЛР №8 находится
в соседнем `../storefront` и работает на Next.js.

## Структура

```text
src/
├── main.tsx                    # Подключение CSS, BrowserRouter и запуск React
├── app/
│   └── App.tsx                 # Маршруты, общая композиция, выбранное блюдо и модальные окна
├── pages/
│   ├── Menu.tsx                # Меню с поиском и категориями
│   ├── Orders.tsx              # Загрузка заказов, оплаты, отмены и выбор подробностей
│   ├── DemoPayment.tsx         # Экран подтверждения/отказа демо-платежа
│   ├── Assistant.tsx           # Диалог с ассистентом
│   ├── Operations.tsx          # Кухня и действия курьера
│   └── Help.tsx                # Справка
├── components/
│   ├── ui/                     # Modal, ErrorBox, Empty, Badge
│   ├── layout/                 # Header, Footer
│   ├── auth/                   # Login: форма входа и регистрации
│   ├── checkout/               # Checkout: порции, сумма и переход к оплате
│   ├── menu/                   # MenuHero, FoodCard, FoodArt
│   └── orders/                 # OrderCard, OrderDetails с живым трекингом
├── hooks/
│   ├── useSession.ts           # Восстановление сессии, выход, session-expired
│   └── useMenu.ts              # Общие данные меню, загрузка, ошибка и повтор
├── lib/
│   ├── api.ts                  # HTTP, refresh, авторизация, POST и SSE трекинга
│   └── format.ts               # Рубли, пользовательские сообщения и подписи статусов
├── types.ts                    # Типы User, Item, Order, Payment, Delivery и ответов AI
└── style.css                   # Общие стили существующего дизайна
```

`main.tsx` содержит 10 строк вместо прежних 1460. `App.tsx` содержит 114 строк;
он собирает приложение, а не рисует карточки и формы самостоятельно.

## Как читать код

Для оформления заказа: `pages/Menu` → `components/menu/FoodCard` → выбранное
блюдо в `app/App` → `components/checkout/Checkout` → `lib/api` → FastAPI.
`Checkout` сначала получает заказ с серверной суммой, затем создаёт платёж с
постоянным Idempotency-Key. Перенос по файлам не меняет платёжный протокол.

Для личного кабинета: `pages/Orders` получает данные и выполняет действия;
`OrderCard` показывает один заказ и вызывает переданные callbacks. Подробности
и подписка на статус доставки находятся в `OrderDetails`.

Для авторизации: `useSession` восстанавливает пользователя, `Login` показывает форму,
`lib/api` хранит access token в памяти и обновляет его через HttpOnly refresh cookie.
`Header` получает пользователя и обработчики через props; сетевых запросов в шапке нет.
Состояние выбранного блюда остаётся в App, потому что его используют и меню, и модальное окно.

Новые страницы добавляются в `pages/`, маршруты — в `app/App.tsx`.
Общие визуальные элементы — в `components/ui/`. Хуки нужны для общей логики состояния,
а функции без React — в `lib/`. Большую карточку удобнее вынести в компонент, чем
увеличивать JSX страницы. Для этого размера приложения глобальный state manager не требуется.

## Запуск

```bash
npm ci
npm run dev
```

По умолчанию Vite проксирует `/api` в FastAPI на `127.0.0.1:8000`,
`/menu*` и `/_next` — в Next.js на `127.0.0.1:3001`.
Для другого адреса API: `SIRIUS_API_URL=http://127.0.0.1:8092 npm run dev`.
За общим Docker nginx те же пути распределяются между сервисами `api`, `storefront` и SPA.

Сборка: `npm run build` — TypeScript и Vite.

## Проверки

`e2e/components.spec.ts` проверяет приложение в браузере с изолированными HTTP-ответами:
поиск, категории, количество порций, регистрацию, демо-оплату, восстановление сессии,
карточку заказа, модальное окно и Escape, отмену/возврат, ассистента, выход/вход,
действия курьера, справку, 404, повтор после ошибки и мобильную ширину.
Это UI-проверки; они не подтверждают реальные финансовые операции или работу брокера.

```bash
npm run build
npm run preview -- --host 127.0.0.1 --port 4174 --strictPort
# В другом терминале:
SIRIUS_BASE_URL=http://127.0.0.1:4174 npm run test:e2e -- e2e/components.spec.ts
```

Нужен Chromium Playwright. Для уже установленного браузера можно задать
`PLAYWRIGHT_CHROMIUM_EXECUTABLE`.
Существующий `e2e/checkout.spec.ts` предназначен для отдельного demo-стенда с настоящим API
и проверяет более широкий сценарий интеграции; в этой проверке он повторно не запускался.

Также после рефакторинга повторно прошёл `storefront/scripts/verify-handoff.mjs`:
настоящий FastAPI с in-memory хранилищем → Vite SPA → `/?item=1` → форма выбранного блюда.
Рабочая база и ЮKassa в проверках рефакторинга не использовались.
